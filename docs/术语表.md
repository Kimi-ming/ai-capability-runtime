# OpenCap 术语表

本文维护 OpenCap 文档中高频术语的统一含义。协议名、字段名、包名和 profile id 保留英文。

## 核心对象

| 术语 | 含义 | 关联文档 |
| --- | --- | --- |
| Capability | 一个可被 AI Host 发现和调用的能力定义。V1 只支持 `type: http`。 | [产品规格](SPEC.md), [能力清单](规范/capability-manifest.md) |
| Capability Manifest | `manifest.yml` 中的机器可读能力声明，包含输入、输出、权限、auth、执行方式和 metadata。 | [能力清单](规范/capability-manifest.md) |
| Capability Package | Registry 中的能力目录，至少包含 `manifest.yml`、`README.md` 和 `tests/*.yml`。 | [能力包结构](设计/capability-package-v1.md) |
| Runtime | 本地或自托管的执行和治理层，负责 policy、consent、secret resolution、execution、audit 和 result boundary。 | [Runtime Kernel 公共契约 V1](设计/runtime-kernel-contract-v1.md) |
| Installed Capability | 已复制到本地 state dir 的 Capability。Runtime 只执行 installed copy，不直接执行 registry 源目录。 | [本地状态 V1](设计/local-state-v1.md) |
| Registry | Git-based Capability 注册表源数据。V1 默认从本地 checkout 的 `registry/` 安装。 | [注册表分发模型](生态/registry-distribution.md) |
| Registry Index | 从 Registry 生成的发现索引。它只加速 discovery，不替代 manifest 原文。 | [Registry Index Signing RFC](../rfcs/0013-registry-index-signing-v1.md), [Registry Index Cache Sync RFC](../rfcs/0014-registry-index-cache-sync-v1.md) |

## 治理和安全

| 术语 | 含义 | 关联文档 |
| --- | --- | --- |
| Policy | 本地策略规则，所有调用必须先经过 policy，再进入 secret resolution 和执行。 | [策略 DSL V1](设计/policy-dsl-v1.md) |
| Consent | 用户对 `ask` 决策的可审计确认对象。MCP Host 无确认通道时返回 `confirmation_required`。 | [确认与同意 V1](设计/confirmation-and-consent-v1.md) |
| Audit Log | 本地审计日志。allow、deny、ask 拒绝、未确认、失败和未知结果都必须可记录。 | [审计日志 V1](设计/audit-log-v1.md) |
| Usage Event | 从 audit log 派生的 non-billing 用量摘要。V1 固定 `billingEffect=none`，不能作为账单记录。 | [用量计量 V1](运营/usage-metering-v1.md) |
| Secret Resolver | 运行时私有的凭据解析层。V1 只支持 env provider，不把 secret 原文写入日志或 result。 | [Secret Resolver V1](设计/secret-resolver-v1.md) |
| Outbound Policy | 控制 HTTP 执行目标的网络边界，默认阻断 localhost、私网、metadata service 和未授权任意 URL。 | [最小出站策略](安全/outbound-policy-v1.md) |
| Data Egress Gate | secret resolution 前的数据外发决策，基于字段、数据类别、目的地和 policy 评估。 | [数据外发策略](设计/data-egress-policy-v1.md) |
| Token Passthrough | 把 Host/client/input token 当作下游 provider token 使用。OpenCap 禁止这种模式。 | [Token Passthrough 禁止](决策/0028-token-passthrough-is-forbidden.md) |
| Breakglass | 紧急 override 通道。它不能绕过审计、egress deny、outbound block、secret ordering 或 revoked block。 | [Policy Override](安全/policy-override-and-breakglass-v1.md) |

## 信任、证据和来源

| 术语 | 含义 | 关联文档 |
| --- | --- | --- |
| Trust Level | Registry/Review 层的离散信任状态。它是 evidence summary，不是 policy。 | [信任模型 V1](生态/trust-model-v1.md) |
| Trust Card | 面向用户的能力信任摘要，展示 tests、review、advisory、maintainer、quality 和 provenance。 | [信任模型 V1](生态/trust-model-v1.md) |
| Quality Score | 非安全认证的质量评分，解释成熟度；`policyEffect` 固定为 `none`。 | [能力质量评分](质量/capability-quality-score.md) |
| Lifecycle | Capability 的 deprecated/yanked/revoked 等治理状态。revoked 记录必须保持可寻址。 | [弃用与撤销](生态/capability-deprecation-and-revocation.md) |
| Advisory | Registry 中的安全或治理公告 metadata，用于记录 freeze/revoke/fixed 等状态。 | [Capability Advisory 流程](安全/capability-advisory-process.md) |
| Provenance | package、release、input 或 result 的来源和转换证据。它不能替代 policy 或 trust review。 | [签名和来源证明路线图](安全/signing-and-provenance-roadmap.md) |
| SLSA | 供应链来源证明语言。OpenCap 预留 metadata，但不把 SLSA evidence 当作自动授权。 | [签名和来源证明路线图](安全/signing-and-provenance-roadmap.md) |
| Sigstore | 面向软件签名和透明日志的生态。OpenCap 预留 future Sigstore 字段，不把签名等同于安全认证。 | [签名和来源证明路线图](安全/signing-and-provenance-roadmap.md) |

## 互操作和结果边界

| 术语 | 含义 | 关联文档 |
| --- | --- | --- |
| MCP | Model Context Protocol。OpenCap V1 通过 MCP tools/list 和 tools/call 暴露已安装能力。 | [MCP 接口 V1](设计/mcp-interface-v1.md) |
| Tool Projection | Runtime 把 Installed Capability 投影成 Host 可见 tool metadata 的过程。 | [Tool Projection V1](设计/tool-projection-v1.md) |
| Result Envelope | Runtime 输出边界。provider response 必须先验证、脱敏、净化、限长并加 evidence。 | [Result Envelope V1](设计/result-envelope-v1.md) |
| Structured Content | 机器可读结果内容。声明 output schema 时，成功结果必须先通过 schema validation。 | [结果交付边界](生态/result-delivery-boundary.md) |
| Taint Label | result provenance 中的字段来源标签，例如 `provider_untrusted`、`runtime_generated`、`secret_redacted`。 | [Result Provenance V1](质量/result-provenance-v1.md) |
| Interoperability Profile | 互操作 profile id 和 evidence schema，用于说明 Host/adapter 兼容声明的边界。 | [互操作 Profiles](生态/interoperability-profiles.md) |
| Paid Capability Manifest Metadata | future `opencap.paid_capability.manifest.v1` metadata，用于展示和 review 付费提示，不能执行购买、扣费或授权。 | [Paid Capability Manifest RFC](../rfcs/0019-paid-capability-manifest-v1.md) |
| Commerce Profile | future `opencap.commerce_profile.v1`，用于交易证据分层。它不能替代 Runtime policy、consent、financial gate 或 audit。 | [Commerce Profile RFC](../rfcs/0020-commerce-profile-v1.md) |

## 维护规则

- 新增高频术语、profile id、schema 字段或安全边界时，同步本文件。
- 如果术语会影响开发任务或发布口径，同步 [文档索引](INDEX.md)、[中文文档中心](README.md) 和 [当前状态交接](HANDOFF.md)。
- 术语定义应说明它不能替代什么，尤其是不能替代 policy、consent、audit 或 review 的字段。
